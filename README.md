# Scrapline

**Компактный мобильный roguelite о строительстве автоматической боевой фабрики.**

Игрок не бегает и не стреляет. Перед началом каждой волны на ограниченной клеточной сетке (например, 7x9) он проектирует инженерное чудовище: производственную цепь из конвейеров, модификаторов и пушек. Во время боевой фазы система оживает, ресурсы бегут по трубам и конвейерам, сливаются в огромные снаряды или расщепляются в рой лазеров, а турели автоматически уничтожают наступающих врагов.

Сможет ли ваша фабрика пережить следующую волну?

## Статус проекта
**Текущая стадия:** Design & Core Prototype (Phase 0-1). Проект находится на этапе проверки основных гипотез и прототипирования базовых механик.

## Ключевые особенности
* **Глубина через взаимодействие:** Мало базовых правил — много неожиданных комбинаций. `Shell + Enlarger + Explosive = Big Bertha`.
* **Визуальная наглядность:** Игрок видит поток производства. Физический или визуально понятный путь ресурса от добычи до попадания во врага.
* **Ограниченное пространство:** Сетка мала, и пространство — главный ресурс. Оптимизация расположения важнее бездумного спама пушками.
* **Roguelite-структура:** Быстрые забеги (15-25 минут), выбор наград (1 из 3) между волнами, новые вызовы в каждой зоне.

## Gameplay Loop
1. **Строительство (Build Phase):** Размещение процессоров, модификаторов и оружия.
2. **Запуск (Combat Phase):** Автоматический бой, где фабрика работает сама по себе.
3. **Награда (Reward):** Выбор новых модулей, чертежей или улучшений (Draft).
4. **Адаптация (Adaptation):** Перестройка фабрики под новых врагов.

## Design Pillars
1. **Инженерное удовольствие:** Удовлетворение от создания машины, которая работает сама по себе.
2. **Короткий цикл обратной связи:** Быстрые волны, мгновенный визуальный результат изменений.
3. **Читаемость:** Визуально понятные причинно-следственные связи без копания в таблицах цифр.
4. **Мобильный UX:** Простое управление (Drag&Drop, Tap), читаемый интерфейс для телефонов.

## Технологический стек
* **Движок:** Godot 4.x
* **Целевые платформы:** Android (Primary), iOS / PC (в перспективе, без изменения архитектуры)
* **Язык логики:** GDScript (в критических узлах C++ / GDExtension, если потребуется)

## Правила разработки
* **Сначала доказать механику — потом делать контент.**
* **Data-driven first:** Новое оружие или враг должны добавляться через файлы ресурсов (.tres), а не через хардкод или копипаст логики.
* **Уважай мобильный UX:** Любая механика должна проверяться на читаемость на маленьком экране и удобство управления одним пальцем.
* **Минимизация `_process`:** Мы ценим батарею телефона. Использовать Event-driven подход и Object Pooling.

## Roadmap (Краткий)
* **Phase 1 (Core Prototype):** Базовая сетка, 2-3 здания, простейший генератор врагов. Цель: доказать интересность core loop.
* **Phase 2 (MVP):** 1 ветка технологий, базовые синергии, 1 короткий забег с экраном победы/поражения.
* **Phase 3 (Vertical Slice):** Добавление UI, VFX, мета-прогрессии, баланс, стартовый контент, обучение.
* **Phase 4 (Alpha):** Расширение контента (больше фракций, врагов, боссов), полировка.
